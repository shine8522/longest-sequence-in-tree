Longest Increasing Path in a Matrix

Suppose you're sitting in an interview and the interviewer gives you a DSA question you've never solved before. How do you approach it?

Let's solve this one together. No jumping to "it's DP" — each observation should make the next one obvious.

1 · The question

What are we asked?

Given an n × m matrix, find the length of the longest path where every next value is strictly greater, moving only up / down / left / right, staying inside the matrix. Diagonals are not allowed.

Press a button.
2 · First observations

What are we actually looking for?

The longest among all valid increasing paths. Many valid paths can exist, so stopping at the first one proves nothing — we must consider the options and keep the maximum.

Click a cell: where can we move from here?

For each neighbor we ask: inside the matrix? AND value greater than current? Only then can we move.

Where does the path start?

We don't know — so try every cell as a start.

Start at (0,0)…

Why not only (0,0)? Take row 5 1 2 3: from 5 no neighbor is greater (length 1), but starting at the 1 gives 1→2→3 = 3. The best path can start anywhere — not necessarily the minimum, not necessarily the corner.

Why explore several options?

From a cell 6 with greater neighbors 7 and 8, we can't pick one blindly. Even "pick the largest neighbor" fails: in [[1,9],[2,3]] greedy goes 1→9 (length 2), but 1→2→3→9 has length 4. We must try both and take the max. Trying all choices from the same kind of subproblem — that's recursion.

3 · Recursion

Define find(i, j)

find(i,j) = longest increasing path starting at cell (i,j).
find(i,j) = 1 + max( find(v) for every valid greater neighbor v ), and = 1 if there is none.

Base case is "no valid greater neighbor ⇒ 1" — the cell alone is a path. Bounds are checked before each call, so no i>=n && j>=m base case is needed (that condition would be wrong anyway).

5 · Overlap → memoization
Same cell, same answer


Run the plain version to the end: find(1,1) appears twice (via (0,1) and via (1,0)), and find(2,2) six times. Two different paths reached the same cell. Does the answer from that cell depend on how we got there? No. Once standing at (i,j), the future choices are identical.


The path used to reach a cell doesn't affect the answer from that cell.
So the state is just (i, j), and dp[i][j] = longest increasing path starting at (i,j).

7 · Complexity
O(n·m) time


There are n×m states; each is computed once and inspects ≤ 4 neighbors ⇒ Time O(n·m). Space: dp table O(n·m) + recursion stack up to O(n·m) in the worst case (a snake-like increasing path) ⇒ auxiliary O(n·m). Plain recursion without memo is exponential in the worst case.


Do we need a visited array?


No. Every move needs next > current, so values strictly increase along any path. Returning to an earlier cell would require its value to be greater than itself — impossible. Cycles can't exist, so no visited array or backtracking is needed. (This is recursion + memoization, not backtracking, and not tabulation.)

9 · Say it in 30 seconds


"I'll treat every cell as a possible start. From a cell I explore its four neighbors and only move to one that's strictly greater. Since several choices can exist, I recursively explore all and take the maximum length. The same cell can be reached by different paths, but the longest path starting from it is always the same, so I memoize per (i,j). That's n·m states with 4 checks each: O(n·m) time and O(n·m) auxiliary space for the dp table and recursion stack."
